SECTION B — EOD EDITABILITY (Re-open Closing for Editing)
================================================================================

  ─── STATUS: ❌ PENDING ───

  ─── Web implementation (app.js) ───

  Three additions to the state model:
    1. dayDate — tracks which calendar date the business day started on
    2. dayArchived — whether day's sales have been archived to history
    3. launchCount — how many times the user has visited morning.html

  ─── completeDay() changes ───
  Instead of pushing to history every time, it now:
    - Sets dayOpen = false (keeps dayArchived = false)
    - Creates/overwrites today's history entry (finds by date, replaces if exists)
    - Keeps data available for editing (no data loss on close)

  ─── closeDayAndShowMorning() changes ───
  No longer resets todayExpenses/todayEarnings to 0 — preserves closing data.

  ─── reopenClosing() — NEW function ───
    1. Finds today's history entry
    2. Restores todayExpenses and todayEarnings from that entry
    3. Sets dayDate = todayStr(), dayOpen = true, dayArchived = false
    4. Navigates to closing.html?edit=true

  ─── archiveDaySales() — NEW function ───
    1. Copies today's sales to the history entry
    2. Removes those sales from active state.sales array
    3. Sets dayArchived = true

  ─── startDay() changes ───
  Now checks if state.dayDate differs from todayStr() and calls
  archiveDaySales() if so — archives old day before starting fresh.

  ─── renderMorningCheck() changes ───
  Context-aware button:
    - Day open → "Close Store" → showClosingScreen
    - Day closed today, not archived → "Edit Today's Closing" → reopenClosing
    - Default → "Start the Day" → startDay

  ─── closing.html changes ───
  - "Edit Closing" button added to summary overlay
  - Closing page in edit mode (?edit=true) shows "Update Closing" instead of
    "Day Complete"

  ─── Android implementation plan ───
