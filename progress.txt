PROJECT OVERVIEW
--------------------------------------------------------------------------------
A native Android sari-sari store management app built with Kotlin and Jetpack
Compose. Ported from the HTML/CSS/JS prototype (git/Sari-sari_smart/).

All 5 frontend stages + Room Database + Testing:
  Stage 1 — Project Foundation ✓
  Stage 2 — 16 Screens with full UI ✓
  Stage 3 — Tutorial System (12 page-specific tutorials) ✓
  Stage 4 — Room Database (5 entities, 5 DAOs, AppDatabase, AppRepository) ✓
  Stage 5 — UX Polish (snackbar, confirmations, nav badges) ✓
  Tests  — 35 Room DAO unit tests (all passing) ✓

Three pillars: Stock Tracker | Daily Cash Summary | Utang Notebook

================================================================================
APP ARCHITECTURE (Current)
================================================================================

Tech Stack:
  - Language: Kotlin 2.0.21
  - UI: Jetpack Compose + Material3
  - Navigation: Navigation Compose
  - Persistence: Room Database (5 entities, 5 DAOs, AppDatabase, AppRepository)
  - DI: Manual (SariSariApp.applicationContext)
  - State: StateFlow in AppViewModel, auto-saved via Room state flows
  - Testing: 35 DAO instrumented tests (Room in-memory database)

Package Structure:
  com.example.sari_sari_smart/
    ├── data/
    │   ├── Models.kt              — Product, DailyEntry, SpecificSale, etc.
    │   ├── AppRepository.kt       — Wraps all 5 Room DAOs
    │   ├── SnackbarManager.kt     — CompositionLocal for global snackbar
    │   └── local/
    │       ├── AppDatabase.kt     — Room database singleton
    │       ├── Converters.kt      — Type converters
    │       ├── dao/               — 5 DAOs (Product, DailyEntry, SpecificSale,
    │       │                        CustomerDebt, EndOfDay)
    │       └── entity/            — 5 Room entities with toDomainModel()/fromDomainModel()
    ├── ui/
    │   ├── components/            — TutorialOverlay, TutorialHighlightState,
    │   │                            SaleBottomSheet, DeveloperPanel
    │   ├── localization/          — Strings.kt (200+ EN/FIL pairs), AppSettings.kt
    │   ├── navigation/            — NavGraph.kt, BottomNavBar.kt, Routes.kt
    │   ├── screens/               — 20 screens (3-moment: Morning/Day/Closing
    │   │                            + 17 support screens)
    │   └── theme/                 — Color.kt, Theme.kt, Type.kt
    ├── MainActivity.kt
    └── SariSariApp.kt

    Tests:
    └── androidTest/
        └── .../dao/               — ProductDaoTest, DailyEntryDaoTest,
                                     CustomerDebtTest (35 tests, all passing)

BUG FIX — TUTORIAL REPEATS ON EVERY NAVIGATION (July 14, 2026)
================================================================================
  Status: [100%] ✓ Complete
  Timeline: ~5 minutes

  Problem:
  ─────────────────────────────────────────────────────────────────────────
  The tutorial auto-started every time the user navigated to the Morning
  screen within the same app session (e.g., after completing closing and
  tapping "Prepare for Tomorrow"). `LaunchedEffect(Unit)` in NavGraph.kt
  fired on every composition of the MORNING route, incrementing
  `launchCount` and re-triggering `startTutorial()`. This caused the
  tutorial to repeat on every internal navigation instead of only on
  fresh app launches.

PHASE 14 — DAYSTATCARD VERTICAL CENTERING FIX (July 28, 2026)
================================================================================
  Status: [100%] ✓ Complete
  Date: July 28, 2026
  Timeline: ~1 hour (including fixing wrong project)

  Overview:
  ─────────────────────────────────────────────────────────────────────────
  The content within DayStatCard composables was not vertically centered,
  especially noticeable when cards had different label lengths or at larger
  text sizes. The fix replaced the intrinsic-measurement-based layout with
  a fixed-height Row approach, matching the web app's predictable CSS Grid
  behavior.

  Root cause:
  ─────────────────────────────────────────────────────────────────────────
  The original layout used Row(height(IntrinsicSize.Min)) + fillMaxHeight()
  which created a circular measurement dependency: the Row's height depended
  on children's intrinsic heights, but children's Box(fillMaxSize) depended
  on the Row's height. This meant contentAlignment = Center had no guaranteed
  extra space to distribute — the Box was exactly the content height.

  Fix applied:
  ─────────────────────────────────────────────────────────────────────────
  [MOD]  ui/screens/DayModeScreen.kt
         • Row: .height(IntrinsicSize.Min) → .height(150.dp) (fixed height)
         • DayStatCard: Removed .heightIn(min = 140.dp) from modifier chain
           (no longer needed with fixed Row height)
         • DayStatCard composable: Replaced Column(padding(12), CenterHorizontally)
           with Box(fillMaxSize, contentAlignment = Center) wrapping
           Column(padding(horizontal=10, vertical=12), CenterHorizontally)
         • Box fills the full 150dp card height, then contentAlignment = Center
           vertically centers the inner Column — guaranteed extra space
         • 2nd card iconBg: hardcoded Color(0xFFE0F2FE) → Blue50 (theme constant)
         • 2nd card icon: 💵 → 📦 (more appropriate for "Items Sold")

  Comparison:
  ─────────────────────────────────────────────────────────────────────────
  
                    | Before (IntrinsicSize.Min)          | After (fixed 150dp)
  ──────────────────|────────────────────────────────────|────────────────────────────
  Row height        | IntrinsicSize.Min (= content)      | 150dp (fixed, predictable)
  Card equal height | ✅ IntrinsicSize.Min + fillMaxHeight| ✅ fillMaxHeight fills 150dp
