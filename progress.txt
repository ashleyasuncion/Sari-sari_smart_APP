PROJECT OVERVIEW
--------------------------------------------------------------------------------
A native Android sari-sari store management app built with Kotlin and Jetpack
Compose. Ported from the HTML/CSS/JS prototype (TindaGo web app).

Originally built as "Sari-Sari Smart" (July–Aug 2026). Rebranded to "TindaGo"
on Aug 18, 2026.

All 5 frontend stages + Room Database + Notifications + Testing:
  Stage 1 — Project Foundation ✓
  Stage 2 — 16 Screens with full UI ✓
  Stage 3 — Tutorial System (12 page-specific tutorials) ✓
  Stage 4 — Room Database (9 entities, 9 DAOs, AppDatabase, AppRepository) ✓
  Stage 5 — UX Polish (snackbar, confirmations, nav badges) ✓
  Stage 6 — Local Notifications (WorkManager, 4 channels, rules + throttle) ✓
  Tests  — 89 unit tests (all passing) ✓

Three pillars: Stock Tracker | Daily Cash Summary | Utang Notebook

================================================================================
APP ARCHITECTURE (Current)
================================================================================

Tech Stack:
  - Language: Kotlin 2.0.21
  - UI: Jetpack Compose + Material3
  - Navigation: Navigation Compose
  - Persistence: Room Database (9 entities, 9 DAOs, AppDatabase, AppRepository)
  - Settings: DataStore (tindago_prefs)
  - Notifications: WorkManager + NotificationCompat (4 channels)
  - DI: Manual (TindaGoApp.applicationContext)
  - State: StateFlow in AppViewModel, auto-saved via Room state flows
  - Testing: 89 unit tests (ViewModel + notification rules + throttle)

Package Structure:
  com.example.tindago/
    ├── data/
    │   ├── Models.kt              — Product, DailyEntry, SpecificSale, etc.
    │   ├── AppRepository.kt       — Wraps all 9 Room DAOs
    │   ├── SnackbarManager.kt     — CompositionLocal for global snackbar
    │   ├── TimeUtils.kt           — Date/time helpers
    │   ├── local/
    │   │   ├── AppDatabase.kt     — Room database singleton (tindago_db)
    │   │   ├── Converters.kt      — Type converters
    │   │   ├── dao/               — 9 DAOs (Product, DailyEntry, SpecificSale,
    │   │   │                        CustomerDebt, EndOfDay, RestockLog,
    │   │   │                        DebtPayment, DebtTransaction, Expense)
    │   │   └── entity/            — 9 Room entities
    │   └── notifications/
    │       ├── AppForegroundTracker.kt — Suppresses pushes while app is open
    │       ├── DailyCheckWorker.kt     — WorkManager worker, twice daily
    │       ├── NotificationCenter.kt   — Notification posting + deep links
    │       ├── NotificationChannels.kt — 4 channel definitions
    │       ├── NotificationRules.kt    — Pure rule logic
    │       └── NotificationThrottle.kt — Cooldown/pinning logic
    ├── ui/
    │   ├── components/            — TutorialOverlay, TutorialHighlightState,
    │   │                            DeveloperPanel, NotificationPrimerDialog,
    │   │                            AppHeader
    │   ├── localization/          — Strings.kt (EN/FIL), AppSettings.kt
    │   ├── navigation/            — NavGraph.kt, BottomNavBar.kt, Routes.kt
    │   ├── screens/               — 20 screens (3-moment: Morning/Day/Closing
    │   │                            + 17 support screens)
    │   └── theme/                 — Color.kt, Theme.kt, Type.kt
    ├── MainActivity.kt
    └── TindaGoApp.kt

V2.0e — BUG FIX: CATEGORY CHIPS EXPAND NOW WRAPS (MOBILE) — DONE
Date: Aug 19, 2026
Status: IMPLEMENTED + VERIFIED

PROBLEM:
- V2.0b used LazyRow for both collapsed and expanded states
- When expanded, all 21 chips were stuffed into one LazyRow, making the
  horizontal scroller longer instead of wrapping to multiple lines
- Web version correctly uses flex-wrap:wrap when expanded

- Switched from single LazyRow to conditional layout:
    Collapsed: LazyRow (horizontal scroll, 6 chips + "More ▾")

- Added @OptIn(ExperimentalLayoutApi::class) for FlowRow

WHAT CHANGED (code):
- StocksScreen.kt: added import FlowRow (from foundation.layout)
- StocksScreen.kt: wrapped chip layout in if/else — LazyRow when collapsed,
  FlowRow when expanded
- StocksScreen.kt: added @OptIn(ExperimentalLayoutApi::class) annotation

FILES AFFECTED:
  ui/screens/StocksScreen.kt
